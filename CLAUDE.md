# Cinema Platform

White-label cinema booking platform: native iOS app, NestJS backend, Next.js operator admin. Detailed specs live in `docs/`; the prioritised backlog is `TASKS.md`.

## Layout
- `packages/contracts` – shared TypeScript schemas (zod): themes + WCAG contrast, tenant config, auditorium layout geometry. Source of truth for cross-platform shapes. Swift mirrors live in `ios/Packages/CinemaKit/Sources/CinemaCore/Models`.
- `backend` – NestJS modular monolith, Prisma/PostgreSQL. Customer API under `/v1/t/{tenant}`, operator API under `/v1/admin`. OpenAPI at `/docs`, exported to `shared/openapi/openapi.json`.
- `admin` – Next.js 15 operator portal (port 3001).
- `ios` – `Packages/CinemaKit` (SwiftPM) + thin app target generated by XcodeGen (`ios/project.yml`).
- `shared/fixtures` – fictional layouts, artwork and published tenant configs used by backend seed, iOS tests and the bundled fallback config.

## Commands
```bash
pnpm install && pnpm build:contracts          # always rebuild contracts after editing them
cd backend && pnpm db:migrate && pnpm db:seed # Postgres from backend/.env
cd backend && pnpm dev                        # API on :3000
cd backend && pnpm test                       # unit + integration (uses cinema_test DB)
cd packages/contracts && pnpm test
cd admin && pnpm dev                          # :3001
cd ios/Packages/CinemaKit && swift test       # CinemaCore tests (macOS or Linux)
cd ios && xcodegen generate && open Cinema.xcodeproj   # Northlight / Kestrel schemes
```

## Rules
- Server is authoritative for holds, prices, booking state and config validity. Clients display server values; never compute totals client-side.
- Money is integer minor units. Screening times are UTC in storage, shown in the venue time zone.
- Every tenant-scoped query filters by `tenantId`. Never accept a tenant id from the request body.
- Mutating customer endpoints that create holds, bookings or payments require an `Idempotency-Key`.
- Published auditorium layouts and config releases are immutable; changes create new versions.
- Brand colours only reach the UI via resolved semantic tokens. No literal colours in views.
- No fake integrations: development adapters must be labelled (simulated payment, demo Wallet state).
- Keep business logic in `CinemaCore` (Linux-testable). SwiftUI targets stay thin; they cannot be compiled on Linux.
- Do not add dependencies without a specific reason recorded in `docs/decisions`.
- Never run `prisma migrate reset` against anything but a disposable local DB; tests use `migrate deploy` on `cinema_test`.

## Testing expectations
Add tests with every behaviour change: backend integration tests for booking/config rules (`backend/test`), Swift Testing for CinemaCore models, vitest for contracts. Report real results only.
